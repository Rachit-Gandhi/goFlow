# Learnings about Manifest v3

## Extension Service Workers
- Special JS environments that handle events and terminate when not needed
- Q: How JS Environments like NodeJS runtime environments? or they run in the browsers JS environment? is there any isolation?
  - **A:** They are **not** like Node.js. They run **inside Chromium** (the same JS engine stack the browser uses—V8 and the browser’s bindings), but in a **dedicated execution context**: the **extension service worker** for your `chrome-extension://<id>/…` origin. You get Chrome’s **extension APIs** (`chrome.*`), not Node’s `process`/`fs` unless you add a native host. **Isolation:** Your extension’s code is **origin-isolated** from normal web pages (different origin, no access to a random page’s JS/DOM from the service worker). Pages are also isolated from your extension except where the platform allows (for example **content scripts** run in an isolated world and talk to the extension via messaging). So: **browser-managed environment + strong separation from sites + different APIs than Node.**

- Q: How do they know they are not needed, do we need to code it up, or is it handled automatically? like garbage collection.
  - **A:** **Handled by the browser, not something you terminate yourself.** Chromium **starts** the extension service worker when an event/API needs it, keeps it alive while **work and timers** imply it may still run, then **shuts it down after idle**. That shutdown is **process lifetime policy**, **not** “JavaScript garbage collection”: GC frees unused objects *while the context is alive*; idle termination **throws away the whole worker** until the next wakeup. Practical guidance from Chrome includes designing for restart (persist via `chrome.storage` / IndexedDB, not fragile long-lived globals) and reading the lifecycle doc for idle-time rules and edge cases. Official overview: [About extension service workers](https://developer.chrome.com/docs/extensions/mv3/service_workers), lifecycle: [The extension service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle).
- If you want to use multiple service workers you can declare the `background` field in your manifest to specify a module and import the workers in your {background Script}.
- After 30 seconds you will see "service worker (inactive)" which means the service worker has terminated. Click the "service worker (inactive)" link to inspect it.
